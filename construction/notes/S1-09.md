# S1-09: the migrate-concept workflow

Task S1-09 (issue #22). Written: `.claude/workflows/migrate-concept.js`. This note records what
the workflow fixes beyond the issue's wording, and what a later task or the maintainer may want
to settle.

## Where the mapping comes from

The thirteen mapping rules (`MAP`, M1 to M13) are the S1-02 prototype's checklist
(`S1-02-prototype.md`) brought up to date with what changed since: the stances live in the
frontmatter only (#97, PR #126), `sources.md` keeps the rows that cite `teaching.md` and the site
filters them (#98), an MDX `<h4>` that `course.yaml` does not list becomes a bold-led paragraph
(ruling on #23), « Objectif » is the `course.yaml` objective that S1-08 merged
(`S1-08.md`). The list is closed: the comparison cites a rule id for every row, and a drop no
rule names is `lost`.

## The report format

One file per concept, `construction/notes/S1-10-<NN>-report.md` (`NN` as in the concept `dir`:
`09`, `A1`), rendered by the script, not by an agent, so its shape cannot drift:

1. a summary table: counts of kept, moved, by design, lost, invented; checks pass or fail;
   accepted or not; the result;
2. one table per old file (CF, SF, MDX, ASTRO): old item, where it is now, verdict, rule,
   detail;
3. « Lost » and « Invented »: the rows the verification confirmed, with its evidence;
4. « Refuted by the verification »: the flagged rows it found carried or produced by a rule;
5. writing choices (merges, inferred `Nature` values, replaced characters, diagram losses);
6. the check command and its output, form fixes, failures left.

Verdicts: the issue names four (kept, moved, lost, invented). The workflow adds **by design**
for an old item a rule drops on purpose (`alignement`, `import` lines, the H1s, the MDX `sources`
paraphrase, the stances hint now in protocol rule 6.1). Without it each of those rows would be
`lost` and every run would fail, or `moved` to nowhere. `by design` never fails a run, and must
cite its rule.

## Beyond the issue's args

`{ course, concept, from, site }` as the issue says, plus:
- `dest`: the course folder written into, default `courses/<course>`. The validation run on
  concept 9 writes into a copy, so the prototype stays as it is;
- `overwrite`: the workflow refuses a target folder that holds files unless it is set (the
  prototype is such a folder on `main`);
- `report`: the report path, default above;
- `langDir`: passed to `check-course --lang-dir`. Until S1-05 (#18) writes `lang/fr.yaml`,
  every check fails on the missing pack; runs pass `specs/linear-course/checks/fixtures/lang`;
- `accept: true` is the issue's `--accept` (a workflow takes args, not flags).

The checks run are the per-concept ones of `checks/README.md` (`course-yaml`,
`concept-folder`, `conventions`, `svg-contract`, `sources`, `glossary-order`) plus
`typography`, with `--concept <n>`. The check agent fixes form only; a failure whose fix would
change what the text says is left and reported, and fails the run.

## Open points, none blocking concept 9

1. **Annex references.** The site printed `<Renvoi n="A2" />` as « annexe A2 ». SPEC.md 4.5 knows
   only `concept`/`concepts`: « concept A2 » would read badly in « dans l'annexe A2 ». M6 keeps
   « annexe A2 » as plain text, not linked. If the site should link it, the spec needs an
   `references.annex` key and the conventions check a form for it. Six site pages use it
   (concepts 0, 4, 10, 11, 15, 16).
2. **Numbered diagram components.** Twenty of the twenty-two components are `Schema<NN>`
   (`Schema16Prevision` included); two of them, 13 and 14, take a `p` variant, each used three
   times. M11 names their SVG by two
   to four words of their `<title>` (a component name such as `schema-13-a` says nothing, and
   the glossary bans "schema" for a diagram). It is the one place where a stem is an agent's
   choice; the report lists it.
3. **Diagram `subconcept` for a diagram in « L'essentiel »** (the cake of concept 9): M11 takes
   the first-level sub-concept it draws, as the prototype did (`9a`).
4. **Validation.** The run on concept 9 and its semantic diff with the prototype are in the PR.
   The first run (0 lost, 0 invented, one check failure) changed four rules: M10 (a reference id
   named only in the verification column goes to the source column; a kind-less MDX claim keeps
   an empty `Nature`), M11 (one-colour readability: distinct opacities, cut lines as gaps, legend
   swatches drawn like their element; group ids on the leaf), M13 (straight apostrophes).
   The second run showed the M10 change over-applied: it added to seven rows an id the
   verification column names as a contrast or a nuance, and replaced « aucune » once, and the
   comparison called it moved. M10 now copies source cells as they are, except the orphan
   reference (cited by no source cell, named as support by one row); the comparison treats any
   other change of sourcing as invented or lost, and the verification refutes only the orphan.
   Run 3 (`wf_844a0213-6d2`) passed: 6 kept, 34 moved, 6 by design, 0 lost, 0 invented, checks
   pass; its three Markdown files equal the prototype's but for whitespace, its SVGs differ in
   geometry only. Its report is `S1-09-concept-9-report.md`, beside this note: a copy, named by
   this task, because `S1-10-09-report.md` belongs to S1-10.09, whose run replaces the prototype.
