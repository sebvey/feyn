# S1-09: the migrate-concept workflow

Task S1-09 (issue #22). Written: `.claude/workflows/migrate-concept.js`. This note records what
the workflow fixes beyond the issue's wording, and what a later task or the maintainer may want
to settle.

## Where the mapping comes from

The thirteen mapping rules (`MAP`, M1 to M13) are the S1-02 prototype's checklist
(`S1-02-prototype.md`) brought up to date with what changed since: the stances live in the
frontmatter only (#97, PR #126), `sources.md` keeps the rows that cite `teaching.md` and the site
filters them (#98), an MDX `<h4>` that `course.yaml` does not list becomes a bold-led paragraph
(ruling on #23), « Objectif » is the `course.yaml` objective that S1-08 merged
(`S1-08.md`). The list is closed: the comparison cites a rule id for every row, and a drop no
rule names is `lost`.

## The report format

One file per concept, `construction/notes/S1-10-<NN>-report.md` (`NN` as in the concept `dir`:
`09`, `A1`), rendered by the script, not by an agent, so its shape cannot drift:

1. a summary table: counts of kept, moved, by design, lost, invented; checks pass or fail;
   accepted or not; the result;
2. one table per old file (CF, SF, MDX, ASTRO): old item, where it is now, verdict, rule,
   detail;
3. « Lost » and « Invented »: the rows the verification confirmed, with its evidence;
4. « Refuted by the verification »: the flagged rows it found carried or produced by a rule;
5. writing choices (merges, inferred `Nature` values, replaced characters, diagram losses);
6. the check command and its output, form fixes, failures left.

Verdicts: the issue names four (kept, moved, lost, invented). The workflow adds **by design**
for an old item a rule drops on purpose (`alignement`, `import` lines, the H1s, the MDX `sources`
paraphrase, the stances hint now in the protocol rule `stances-told-apart`). Without it each of those rows would be
`lost` and every run would fail, or `moved` to nowhere. `by design` never fails a run, and must
cite its rule.

## Beyond the issue's args

`{ course, concept, from, site }` as the issue says, plus:
- `dest`: the course folder written into, default `courses/<course>`. The validation run on
  concept 9 writes into a copy, so the prototype stays as it is;
- `overwrite`: the workflow refuses a target folder that holds files unless it is set; set, a
  first agent empties that folder, and only it, and the run stops if it is not empty after.
  Before any emptying, the script checks the folder in code: the concept `dir` must be
  `concepts/<NN>-<slug>/` for this concept, and the target strictly under `<dest>concepts/`;
  the SVG stems are checked the same way. No validation run exercised the emptying (run 4
  wrote into an absent folder): only the stand-in-agent cases did;
- `report`: the report path, default above;
- `langDir`: passed to `check-course --lang-dir`. Until S1-05 (#18) writes `lang/fr.yaml`,
  every check fails on the missing pack; runs pass `specs/linear-course/checks/fixtures/lang`;
- `accept: true` is the issue's `--accept` (a workflow takes args, not flags).

The checks run are the per-concept ones of `checks/README.md` (`course-yaml`,
`concept-folder`, `conventions`, `svg-contract`, `sources`, `glossary-order`) plus
`typography`, with `--concept <n>`. The check agent fixes form only; a failure whose fix would
change what the text says is left and reported. The verdict is read in code from the
output, line by line: any failure of `concept-folder`, `conventions`, `svg-contract`,
`sources` or `glossary-order` fails the run whatever file it names (a missing or broken
language pack is reported against `course.yaml`); a `course-yaml` or `typography` failure,
which may come from elsewhere in the course, is excused only when it names neither this
concept nor the language pack; a check with no line in the output fails the run.

The default `from` and `site` (`../pdx/…`) are relative to the working directory of the run,
which is the repository root only in the main checkout: a run from a worktree or a copy passes
absolute paths. `dest` must hold a full course (`course.yaml` and the course files), the
checks read it. The spec folder is built in code (`specs/<spec>/`, relative to the working
directory), not taken from an agent.

## What the run trusts an agent for

The script has no file access. Decided in code: the target path and the SVG stems (checked
before use), the checks verdict (parsed from the output), the report (rendered in code; the
writing agent returns its size, compared with the rendered one, one byte of slack for a final
newline). Still an agent's word, and the report says so: `target existed` (the scope agent:
the refusal to overwrite `courses/` rests on it), and the check output itself, which the check
agent returns verbatim.

## Blind writers

The writers may read only the old files, the `course.yaml` entry, the spec and its templates.
They are told never to read another copy of the concept (`courses/`, `construction/notes/`,
the repository history, the target before their own write). Runs 1 to 3 had no such rule and
pointed the writers at the prototype and its note: their transcripts show the writers copying
from or diffing against it, so their equality with the prototype proves nothing. A prompt rule
is not a wall: a validation run is done from a copy of the repository without the prototype,
then the run's transcripts are searched for any read of it. The examples inside the mapping
rules were concept 9's own (`concept 3b`, `[S5b]`, `9a1-couches`, `Gateau`): they are replaced
by invented ones, so that the rules do not hand concept 9's answers to its own run. Two
agreements of run 4 with the prototype are not evidence of the rules alone: SPEC.md section 7
itself gives concept 9's ids as its examples (`9a1-couches`, `9a1-tranche-1`, `gateau-titre`),
and M11 asked for gaps between segments, the prototype's own answer to the cut lines.

## Open points, none blocking concept 9

1. **Annex references.** The site printed `<Renvoi n="A2" />` as « annexe A2 ». SPEC.md 4.5 knows
   only `concept`/`concepts`: « concept A2 » would read badly in « dans l'annexe A2 ». M6 keeps
   « annexe A2 » as plain text, not linked. If the site should link it, the spec needs an
   `references.annex` key and the conventions check a form for it. Six site pages use it
   (concepts 0, 4, 10, 11, 15, 16).
2. **Numbered diagram components.** Twenty of the twenty-two components are `Schema<NN>`
   (`Schema16Prevision` included); two of them, 13 and 14, take a `p` variant, each used three
   times. M11 names their SVG by two
   to four words of their `<title>` (a component name such as `schema-13-a` says nothing, and
   the glossary bans "schema" for a diagram). It is the one place where a stem is an agent's
   choice; the report lists it.
3. **Diagram `subconcept` for a diagram in « L'essentiel »** (the cake of concept 9): M11 takes
   the first-level sub-concept it draws, as the prototype did (`9a`).
4. **Validation.** The runs on concept 9 and their diffs with the prototype are in the PR.
   Runs 1 to 3 (not blind) still fixed rules: M10 (the orphan reference only, source cells
   otherwise copied as they are; a kind-less MDX claim keeps an empty `Nature`), M11 (one-colour
   readability), M13 (straight apostrophes), and the comparison's treatment of sourcing changes.
   The validation that counts is the blind run 4 (`wf_aa0a5543-bdb`, from a copy of the
   repository without the prototype; its transcripts show no read of it): 10 kept, 38 moved,
   9 by design, 0 lost, 0 invented, checks pass; `sources.md` and `teaching.md` equal to the
   prototype, `concept.md` equal but for key order, wrapping and one article. Its report is
   `S1-09-concept-9-report.md`, beside this note (paths relative to that copy and to the
   workspace): named by this task, because `S1-10-09-report.md` belongs to S1-10.09. Two SVG
   points where the prototype was right sharpened M11 after run 4: one class-and-opacity pair
   per old colour token, and group ids on the leaf a part illustrates. No run 5 (maintainer,
   2026-10-28): these two changes are tested only with stand-in agents; S1-10 (#23) exercises
   them.
5. **`migrate-work/`.** The scratch folder of runs 1 to 3 is no longer ignored: S1-10 writes
   into `courses/` (the default `dest`), and a blind run lives in its own copy outside the
   repository, so nothing will use it.

**2026-10-28, after the pilot wave of S1-10 (#170).** The pilot wave (concepts 0, 1 and 9; PRs
#168, #167, #169) showed four points, fixed before wave 2:
- **M11, one mapping per concept** (ruling on #23): concept 9's two diagrams mapped `--sch-s2` to
  two different pairs. A colour agent, at the start of the Write step, now decides one
  class-and-opacity pair per old colour token from all the components of the concept; every
  diagram writer receives it, and returns the tokens it draws with. The script checks the form
  (one pair per token, no pair twice, every token a writer uses mapped); the report shows the
  mapping once, in its own section, and the losses no longer repeat it. Point 4 above (« one
  class-and-opacity pair per old colour token ») now holds across the diagrams of a concept.
- **M10, old paths**: the intro and « Non vérifié » kept paths of the old repository
  (`course/plan.md`, ADR-018, `off-course.md`). M10 now rewrites every old path of the file to
  its path in the course folder (an old decision number to the course decision that carries it
  over), and drops, in the intro and « Non vérifié » only, a pointer with no new path. Concepts
  0, 1 and 9, already merged, keep their old paths: #140, the sources pass, handles them.
- **Report paths**: the report now writes paths relative to the course folder and names the old
  files from their repository folder; it held the absolute paths of the run's `dest`.
- **"target existed"**: it was the scope agent's yes or no, and the first run of concept 0
  (`wf_18b79caf-82d`) stopped on a yes for an absent folder. The scope agent now returns the
  `ls -la` output of the target; the script reads it (absent, empty, or holding files) and
  refuses only on a listing that shows files, and the report shows the listing. "What the run
  trusts an agent for" above changes accordingly: the listing itself is still the agent's
  output, but no longer its judgment.

Tested with stand-in agents only (14 cases: one mapping in every writer's prompt, the report
free of absolute paths, each refusal of the listing and of the mapping). The first run of wave 2
is the live test.
