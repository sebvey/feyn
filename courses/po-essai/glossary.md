# Glossaire du cours

Un seul terme par notion : le cours emploie le « terme du cours », en français, ou en anglais quand c'est l'usage. Les variantes d'un terme sont séparées par des virgules ; une parenthèse précise le sens. La colonne « Défini dans » donne le concept à ouvrir pour creuser le terme, celui qui l'enseigne : avant ce concept, le cours n'emploie le terme que dans une phrase qui renvoie à ce concept ou qui le définit en passant. Le prof peut montrer ce fichier à l'apprenant.

| Terme du cours | Anglais | Définition | Défini dans |
|---|---|---|---|
| Scrum | Scrum | Cadre de travail décrit par le Scrum Guide (Schwaber, Sutherland, 2020) | 0 |
| Équipe Scrum | Scrum Team | Le PO, le Scrum Master et les Developers | 0 |
| Product Owner, PO | Product Owner | Personne seule qui répond de la valeur du produit et de l'ordre du backlog | 0 |
| Scrum Master | Scrum Master | Personne qui répond de l'efficacité de l'équipe, dont la levée des obstacles | 0 |
| Developers | Developers | Les membres de l'équipe qui réalisent l'incrément (ici data engineers et analyste) | 0 |
| Responsabilité | accountability | Ce dont répond chacun des trois rôles de l'équipe Scrum (PO, Scrum Master, Developers) | 0 |
| Événement | event | Le sprint et les quatre événements qu'il contient (Sprint Planning, Daily Scrum, revue de sprint, rétrospective) | 0 |
| Artefact | artifact | Ce qui représente le travail ou la valeur : backlog produit, backlog de sprint, incrément | 0 |
| Engagement | commitment | Repère attaché à chaque artefact : objectif produit, objectif de sprint, DoD | 0 |
| Sprint | Sprint | Période fixe d'un mois au plus, qui contient les autres événements | 0 |
| Sprint Planning | Sprint Planning | Événement où l'équipe fixe l'objectif de sprint et où les Developers choisissent, avec le PO, le travail du sprint | 0 |
| Daily Scrum | Daily Scrum | Point quotidien des Developers sur l'avancement vers l'objectif de sprint | 0 |
| Revue de sprint | Sprint Review | Événement où l'équipe et les parties prenantes inspectent l'incrément et adaptent le backlog | 0 |
| Rétrospective | Sprint Retrospective | Événement où l'équipe inspecte sa façon de travailler, DoD comprise | 0 |
| Incrément | Increment | Le produit dans un nouvel état utilisable, qui remplit la DoD | 0 |
| Backlog produit | Product Backlog | Liste ordonnée et émergente de ce qu'il faut pour améliorer le produit, seule source du travail de l'équipe | 0 |
| Objectif produit | Product Goal | Engagement du backlog produit : l'état futur du produit visé à long terme | 0 |
| Objectif de sprint | Sprint Goal | Engagement du backlog de sprint : l'objectif unique du sprint | 0 |
| Definition of Done, DoD | | Engagement de l'incrément : la description de l'état qu'il doit atteindre | 0 |
| Produit (d'une équipe) | product | Ce qui résout un problème d'utilisateurs et leur apporte une valeur | 1 |
| Utilisateur (d'un produit) | user | Personne qui se sert du produit (un consommateur de données en est un) | 1 |
| Partie prenante | stakeholder | Toute personne ou équipe concernée par le produit (utilisateur, financeur, sponsor, équipe voisine, fournisseur de données) | 1 |
| Valeur (d'un produit) | value | Ce que l'utilisateur ou l'organisation gagne (temps, meilleure décision, risque évité) | 1 |
| Sponsor | sponsor | Responsable qui porte le budget du produit et porte plus haut les obstacles qui dépassent le PO, sans ordonner le backlog | 1 |
| Backlog de sprint | Sprint Backlog | Objectif de sprint, éléments choisis et plan des Developers | 0 |

## Termes à éviter

| À éviter | Dire plutôt | Pourquoi |
|---|---|---|
| « livrer un sprint » | « livrer un incrément » | Le sprint est une durée, l'incrément un état du produit |
| « ticket » | « élément du backlog » | Terme d'outil, absent du Scrum Guide |
