# Checks of `linear-course`

Scripts that verify a course against the rules of `course/rules.yaml` (described by `course/README.md`; listed in the MAJOR's `README.md` section 5), run by `check-course`, beside the agent workflow `taught-check.js`, which it does not run (below); the tests of the spec's own files (`teacher/README.md`, `README.md`, `course/README.md`, `decisions/`, `course/rules.yaml`, `teacher/rules.yaml`, `teacher/composition.yaml`, `course/schemas/`, the lexicons of the course files and of the teacher, `spec.yaml`, `CHANGELOG.md`), run by `spec-directives/check-spec`, belong to the spec directives this MAJOR follows (`spec-directives/1/tests/`) and are described in `spec-directives/1/README.md` section 8. Node 20 or later, CommonJS, run under `mise exec` like every tool here, with the `lib/` and the dependencies of the directives MAJOR that the MAJOR's `spec.yaml` declares (`directives: 1`, so `spec-directives/1/package.json`; decision `checks-use-ajv-and-yaml`): `directives.js` reads that line and loads them through a `createRequire` on that `package.json`. The course's YAML is read by the package `yaml` in YAML 1.2 mode, through `lib/yaml-lines.js`, which keeps the line of each key and item so a failure points at `file:line`; ajv compiles the schemas of `course/schemas/` through its class `Ajv2020` (JSON Schema 2020-12); Markdown and SVG are read by the small readers in `lib/` (`md.js`, `xml.js`), which cover the subset the spec uses. Each rule of `course/rules.yaml` names in `check` the script that verifies it, and `check-course` takes its checks from there (`lib/rules.js`). The form of the concept file is read from `course/form.yaml` (`check-course` passes it to `lib/course.js`, which finds the parts of each `concept.md`, its units and their fields, for every check that reads them): `concept-file`, `unit-contract`, `case-coverage` and `teacher-message-length` hold a course to it, and `conventions`, `glossary-order` and `unit-additions` take from its `readers` the parts the learner reads; the form of the course files is read there too, by `course-yaml` (`course_map`) and `course-files` (`plan`, `domain_file`, `storyline`). `course-yaml` validates `course.yaml` through `Ajv2020` and `course/schemas/course.schema.yaml`, and `concept-file` the frontmatter of `concept.md` through `course/schemas/concept-frontmatter.schema.yaml`, a failure mapped from ajv's instance path to its `file:line` (`lineOfError` of `lib/yaml-lines.js`); neither re-checks in its own code what a schema says.

## Install

```
mise exec -- npm ci --prefix spec-directives/1
```

From the repository root, once per clone or worktree, and again when `package-lock.json` changes: `npm ci` installs the locked versions in `spec-directives/1/node_modules/`, which git ignores. The command has no `cd`, so an agent in a worktree can run it. Without it, `check-course`, `test-fixtures`, `course-specs/check-course` and `spec-directives/check-spec` stop with one line giving that command (exit code 2); a missing `spec.yaml`, or a `directives` MAJOR with no folder, stops them the same way.

## Run

```
mise exec -- course-specs/check-course courses/<id>
mise exec -- course-specs/check-course courses/<id> --category pedagogy
mise exec -- course-specs/check-course courses/<id> --only drawing-contract
mise exec -- course-specs/check-course courses/<id> --only concept-file,unit-contract --concept 9
mise exec -- course-specs/linear-course/1/course/checks/check-course --list
```

The checks come from the rule file of a course (`spec-directives/1/README.md` section 5; decision `severity-from-level-and-method`): `check-course` runs, in one run, every check named by the `check` of a rule of `course/rules.yaml` whose method is test. A check's category and level come from its rules, which `rule-files` (`check-spec`) holds to one category and one level per check, and its severity follows: it **blocks** when its rules are requirements verified by test, otherwise it **reports**. A failure of a blocking check sets exit code 1; a failure of a reporting check is printed the same way, its findings triaged into course issues, and leaves exit code 0. The blocking checks run first, then the reporting ones, each in the order of `course/rules.yaml`; no list of checks is written in `check-course`.

A check runs on a course when its method is test and its script is in this folder. The tests of `check-spec` (`spec-directives/1/README.md` section 8) verify no rule: `check-course` neither runs nor lists them. A check of another method is not run here: `taught-check` (analysis) is an agent workflow kept in this folder, `taught-check.js`, which `check-course` does not run, run as `course-specs/linear-course/1/README.md` section 5 says; and a rule verified by inspection has no check, the review reads it. `--list` names every check, the ones not run here with how they run.

`course-specs/check-course` reads `spec: linear-course@<MAJOR>` in the course's `course.yaml` and runs `course-specs/linear-course/<MAJOR>/course/checks/check-course` with the same arguments; it refuses an unknown spec or MAJOR, naming it, with exit code 2. The `spec:` line names the MAJOR, whose `spec.yaml` names, by its `directives:` line, the directives MAJOR whose `yaml` package (in `spec-directives/<MAJOR>/node_modules/`) then reads `course.yaml`: the dispatcher needs that `npm ci` too. This folder's `check-course` runs this MAJOR's checks directly, `--list` with no course included.

One line per passing check (`<id>: ok`), one line per failure (`<id>: fail: <file>:<line> <message>`, the file relative to the course folder), whatever the severity; then one summary line, `summary: <n> blocking checks, <n> failed (<ids>); <n> reporting checks, <n> failed (<ids>); exit <code>`. The exit code is 0 when no blocking check fails, 1 when one fails or a check crashes, 2 on a usage error, when the rule files cannot be read or when the dependencies are not installed.

| Option | Does |
|---|---|
| `--category <c>[,<c>]` | runs the checks of those categories only (repeatable): a closed list, the categories of a course in `course/rules.yaml` (`structure`, `pedagogy`, `writing`, `diagrams`, `sources`); an unknown one is a usage error |
| `--only <id>[,<id>]` | runs those checks only (repeatable); an unknown id (a test of `check-spec` among them), the id of a check not run here, or an id outside `--category` is a usage error |
| `--concept <number>` | the per-concept checks (`concept-file`, `unit-contract`, `unit-additions`, `case-coverage`, `teacher-message-length`, `conventions`, `drawing-contract`, `sources`, `glossary-order`) look at that concept only, and `course-yaml` demands only that concept's folder and does not look for unlisted folders in `concepts/`: for a migration in progress, or a creation concept by concept, when the other concept folders do not exist yet ("The checks of each step of the creation", below) |
| `--lexicon <file>` | reads the lexicon of the course files from `<file>` instead of this MAJOR's `course/lexicon.yaml` (the fixtures' lexicons, `test-fixtures`) |
| `--list` | prints every check of `course/rules.yaml`, `--category` applied, in the order of the run: its id, its category, its severity (`blocks` or `reports`), and for a check not run here, how it runs; no course needed |

The flag `--quality`, removed, is a usage error whose one line names its replacement: the default run, which holds the reporting checks, or `--category`.

## The checks

One script per id, `course/checks/<id>.js`, exporting `run(ctx)`. The category and the severity are those `check-course --list` prints, from the rules, in the order of the run.

| Id | Category, severity | Script | Verifies (course/README.md) |
|---|---|---|---|
| `course-yaml` | `structure`, blocks | `course-yaml.js` | the fields against `course/schemas/course.schema.yaml` through `Ajv2020` (the map of the course: no sections nor units, no public of the course); then what the schema does not say: identifiers, order, domains, annexes, prerequisites, paths, no unlisted folder in `concepts/` (not looked for under `--concept`); a missing or unreadable lexicon, a tooling error (no rule: the lexicon is the spec's, `lexicon-keys` of `check-spec` tests it) (2; `spec-directives/1/README.md` 6) |
| `concept-file` | `structure`, blocks | `concept-file.js` | from `course/form.yaml`: the files of the folder; the frontmatter against its schema through `Ajv2020`, then what the schema does not say (`verified` parallel to `refs`, absent without `refs`; an item's text in inline Markdown); the title, the one `#`, first, `# Concept <n> : <title>` (an annex `# Annexe <id> : <title>`) with the title of `course.yaml`; the parts of `concept.md` in order (head « L'essentiel », sections, foot « Clôture ») and no other `##`, no `###` in the head, the `###` blocks of the foot in their order and nothing else in it; the tree of the concept in its headings (each heading opened by its kind word of `block_kinds`, `## Section <id> : <title>`, `### Unité <id> : <title>`; section and unit ids: form, order, uniqueness, one unit at least and at most 9 per section, a title after each id) (3, 3.1, 3.2) |
| `unit-contract` | `pedagogy`, blocks | `unit-contract.js` | from `course/form.yaml`: a section with units holds them only; each unit's `####` blocks, « Leçon », « Cas du fil rouge », then « Consigne au professeur » when it has one, each titled by its word alone (a heading that carries more than its word, a mark in parentheses, named), the mandatory ones once, in order, no line outside a block; the labelled fields of « Leçon » and « Cas du fil rouge » (known labels, nothing between a label and its colon, none empty), no line outside a field; « Idées fausses » of « Leçon » a list of misconceptions below its label, one at least, each `- **<name>** : « <belief> »`, its name unique in its unit, then « Racine » and « Correction », each once, in that order, none empty, nothing else under it; « Cas du fil rouge » a list of cases, one at least, each under its heading `##### Cas : <title>` (a line before the first heading named, a heading without its kind word or its title named), its fields once and in order, all mandatory, « Idées fausses en jeu » last; the title of every case unique in the concept; « Idées fausses en jeu » names one misconception at least, each a misconception of its unit (a name of another unit's, or one that matches none, named); each misconception of the unit named by a case at least; « Consigne au professeur » not empty (3.3, 7) |
| `conventions` | `writing`, blocks | `conventions.js` | the conventions of the text of `concept.md`, in the parts the learner reads (`readers` of `course/form.yaml`, the instruction left out): concept references, stance markers; no image in `concept.md`; a `####` only inside a unit, a `#####`, a case, only inside a unit, none deeper; plain Markdown in every course file (1, 3.5) |
| `drawing-contract` | `diagrams`, blocks | `drawing-contract.js` | every diagram against the drawing contract, a root `<defs>` accepted; declared and present diagrams, the `unit` of each a unit of the concept (3.1, 6.1) |
| `sources` | `sources`, blocks | `sources.js` | the form of `sources.md`: no frontmatter, no H1, its sections « Affirmations », « Références », « Non vérifié » in this order and no other, one table of five columns in each of the first two; no introduction; in each « Affirmations » row: section anchors that exist in `concept.md` among its published parts, a source cell of reference ids or the `markers.course` word, a verification (empty for a « cours » claim only), a nature (`markers` consensus, school, course, or `natures.fact`); reference ids, links (one URL or empty), types, dates; every id cited exists, every reference is cited by a claim or a frontmatter item; « Non vérifié » entries open with their section; `concept.md` cites no reference (3.1, 3.4) |
| `course-files` | `structure`, blocks | `course-files.js` | from `course/form.yaml`: `plan.md` (« Public cible », « Accueil », « Progression », in this order and not empty; « Accueil »: one posture paragraph, then its questions), the domain files (no frontmatter, no H1, « Le problème » and « Un cas qui traverse le domaine » only, no unlisted file in `domains/`), `storyline.md` (« Faits fixés » last, a bulleted list, each fact ending with the id of a unit of the course), `glossary.md` (four columns, one concept number in the fourth, no variant in two rows), `CHANGELOG.md` (4, 5) |
| `unit-additions` | `pedagogy`, reports | `unit-additions.js` | the additions of a unit, what a program can tell of them: each passage in bold of a field of a unit, those of its cases included, that the learner reads (`readers` of the blocks of `course/form.yaml`: every block but « Consigne au professeur »), the labels left out, is a term of `glossary.md` or one of its comma variants, its qualifier in parentheses left out, case ignored (a recommendation: bold for emphasis stays possible, and a bold that is no term is reported in case the term is missing from the glossary); that a fact an anchor uses is in `storyline.md` and that a claim of a published field has its row in `sources.md` are rules by inspection of its group, and that a fixed fact or a claim names a unit that exists is `course-files`' and `sources`' (3.6) |
| `typography` | `writing`, reports | `typography.js` | no banned character of the lexicon in course text (1) |
| `case-coverage` | `pedagogy`, reports | `case-coverage.js` | the coverage of a unit's case: each misconception of its unit it names in « Idées fausses en jeu » is named by a supplementary case of the unit too; a unit that leaves one to its case alone is reported, its stock lacking a case (`in_play` of the block of cases in `course/form.yaml`) (3.3) |
| `teacher-message-length` | `pedagogy`, reports | `teacher-message-length.js` | the length of one teacher message: the text of « Matière », « Ancrage » and « Question » of each unit, its misconceptions left out, counted in lines of 100 characters (its characters divided by 100): a unit above 12 is reported (`length` of `unit` in `course/form.yaml`) (3.3) |
| `glossary-order` | `pedagogy`, reports | `glossary-order.js` | no `concept.md`, in the parts the learner reads (`readers` of `course/form.yaml`: every block of a unit, the head and the foot, but not the instruction) or its frontmatter (stance and neighbour texts, diagram titles and captions), uses a glossary term before its defining concept (the fourth column), unless the sentence carries a concept reference to that concept (`lib/refs.js`, the grammar `conventions` checks); every use is reported; each comma variant of the term cell is matched whole word, case ignored; a row whose term cell has a parenthesis is skipped (5) |

A claim's source cell holds reference ids (`[S1], [S2]`) or the `markers.course` word (« cours »), nothing else: free text (« aucune », « fil rouge ») and a path to another concept fail. A section anchor is a section or unit id, or a published block of the head or the foot by its lexicon value (the `blocks` of `head` and `foot` in `course/form.yaml` marked `published`: `headings.essentials`, `landmarks`, `deepening`) whose `###` heading exists in `concept.md`; a « Non vérifié » entry is a list item `<anchors> : <text>`, and may also name `headings.stances`. The form of the verified cell (a quotation and its place) is reviewed.

## The checks of each step of the creation

Until `products/creator/` holds the creation path (epic #522), this section names the steps of the creation of a course and the checks each runs. Foundations, once: F1 to F4; then concept by concept, C1 to C5 (C6, teaching the concept, once the teacher is back: decision `teacher-frozen-until-the-protocol-brainstorm`), a concept finished before the next starts; D1 for a domain, once its concepts are written. A step runs its command at once, on what it has just written; `<course>` is `courses/<id>`, `<n>` the number of the concept being written.

The checks stay strict: there is no draft state, and a check reads a whole file or the whole course. A failure that names what a later step writes is that step's work, not a defect: the last column says which ones to expect. A step is done when its command prints no other failure, a bold that `unit-additions` reports and the creator keeps for emphasis excepted. The course is done when `course-specs/check-course <course>`, with no option, exits 0.

| Step | Writes | Runs | Fails until a later step writes it |
|---|---|---|---|
| F1 the frame | the header of `course.yaml` (`id`, `spec`, `title`, `storyline`, `glossary`, `domains: []`, `concepts: []`), `plan.md` « Public cible » and « Accueil », `CHANGELOG.md` with its « Non publié » | `course-specs/check-course <course> --only course-files` | « Progression » (F2); `storyline.md`, `glossary.md` (F4) |
| F2 the course plan | the domains of `course.yaml`, `plan.md` « Progression » | `course-specs/check-course <course> --only course-files` | `storyline.md`, `glossary.md` (F4) |
| F3 the concepts | the concepts of `course.yaml`, in their domains | `course-specs/check-course <course> --only course-yaml,course-files` | each concept's folder (its C1), each domain file (its D1); `storyline.md`, `glossary.md` (F4) |
| F4 the world | `storyline.md`, its world without « Faits fixés »; `glossary.md`, its table without rows | `course-specs/check-course <course> --only course-files` | nothing: it passes |
| C1 the skeleton | `concept.md`: its title, `# Concept <n> : <title>` (an annex `# Annexe <id> : <title>`), the title of `course.yaml`; the sections, `## Section <id> : <title>`, and their units, `### Unité <id> : <title>`, one at least per section, each with its first block, `#### Leçon`, and one line of matter | `course-specs/check-course <course> --concept <n> --only concept-file,unit-contract` | the other blocks of each unit (C2); the frontmatter and the head, « L'essentiel » (C3); `sources.md` (C4) |
| C2 each unit and its additions | a unit's blocks, in the order of writing: teach, `#### Leçon` (« Matière », then « Idées fausses », each misconception named, with its « Racine » and its « Correction »); ask, `#### Cas du fil rouge` (its case, under its heading `##### Cas : <title>`, « Ancrage », « Question », « Réponse attendue », « Idées fausses en jeu », the misconceptions of the unit it makes tempting, then its supplementary cases in the same form, each misconception of the unit named by a case at least); instruct, `#### Consigne au professeur` when the unit has one, the boundary of its matter, only what a competent teacher would otherwise do differently in this unit (rule `instruction-beyond-a-competent-teacher`), where a move of the course goes (rule `course-question-in-instruction`); « Leçon » and « Cas du fil rouge » are published, « Consigne au professeur » never; its additions: a fact an anchor uses, in « Faits fixés » of `storyline.md` naming the unit; a term it puts in bold, in `glossary.md` (`unit-additions` reports a bold that is no term) | `course-specs/check-course <course> --concept <n> --only unit-contract,unit-additions,conventions,course-files,case-coverage,teacher-message-length,glossary-order,typography` | a concept reference to a concept not yet written, and a glossary term of that concept in its sentence (`glossary-order`, which reports) (that concept's C1) |
| C3 the head and foot | the head, `## L'essentiel`, then its text; the foot, `## Clôture`, then its blocks, `### Se vérifier`, `### Approfondissement`, `### Consigne au professeur` (the boundary of the concept's matter, only what a competent teacher would otherwise do differently in the whole concept, rule `instruction-beyond-a-competent-teacher`; a move of the course that holds for the whole concept, rule `course-question-in-instruction`), those it has (no « Clôture » without one); the frontmatter (`stances`, `neighbors`) | `course-specs/check-course <course> --concept <n> --only concept-file,conventions,glossary-order,typography` | `sources.md` (C4); a concept reference to a concept not yet written, as at C2 |
| C4 the sources | `sources.md`: a row of « Affirmations » for each claim of a published field (the third addition of a unit), its references | `course-specs/check-course <course> --concept <n> --only concept-file,sources` | nothing: it passes |
| C5 the diagrams | each diagram, its SVG and its declaration in the frontmatter at its unit | `course-specs/check-course <course> --concept <n> --only drawing-contract,concept-file` | nothing: it passes |
| D1 the domain file | `domains/<number>-<slug>.md`, « Le problème » and « Un cas qui traverse le domaine » | `course-specs/check-course <course> --only course-files,course-yaml` | the folders of the concepts not yet written (their C1), the files of the other domains (their D1) |

`course-yaml` asks for every concept folder and every domain file `course.yaml` names, so it passes only once each exists; under `--concept <n>` it asks for that concept's folder only, but still for every domain file. The rules by inspection of a step (the content of a field, the restatement between a unit's matter and its cases, the facts an anchor uses, the claims to source) are the review's: `course/rules.yaml` lists them in the group of each section of `course/README.md`.

## Tests of the spec itself

The tests of the spec's own files, run by `spec-directives/check-spec <spec-dir>`, belong to the spec directives this MAJOR follows: their list, what each verifies, their fixtures and how to run them are in `spec-directives/1/README.md` section 8.

## Tests

```
mise exec -- course-specs/linear-course/1/course/checks/test-fixtures
```

It tests the course fixtures and the dispatcher; the spec fixtures, under `spec-directives/1/tests/fixtures/`, are tested by `spec-directives/1/tests/test-fixtures` (`spec-directives/1/README.md` section 8). Every course fixture runs once, with the default; the test reads `course/rules.yaml` itself and holds each run's exit code to the severity of the check that fails: 1 for a blocking check, 0 for a reporting one. `--list` must name every check of `course/rules.yaml` with the category and the severity of its rules, and none of the tests of `check-spec`; a run must run every check `--list` does not mark "not run here". `--category` runs the checks of its categories only (`writing`, `pedagogy`, `structure,diagrams`; `broken/drawing-contract` passes with `--category writing`); an unknown category (the name of the spec among them), the flag `--quality`, removed, an id of a test of `check-spec` and an id outside `--category` are usage errors (exit code 2).

- `fixtures/valid/`: a minimal valid course (three concepts, one annex, one diagram with a root `<defs>` declared at its unit; concept files opening on their title, a concept's and an annex's, with a section of two units and sections of a single unit, the three blocks of a unit and a unit without « Consigne au professeur », every field of a unit, misconceptions in « Leçon », several in one unit, each named with its « Racine » and its « Correction », a field on several lines, a « Question » whose text opens on « en deux parties : », a « Cas du fil rouge » with the three types of supplementary case after the unit's case, the three blocks of the foot, a foot with one block, an annex cut into units; a `plan.md` with « Progression » and a section of its own, domain files of two sections, a `storyline.md` whose fixed facts name a unit of a section of two units and the unit of a section of a single one, one of them on two lines; terms in bold in units (a term, a comma variant in a supplementary case, a qualified term) and a bold that is no term in a « Consigne au professeur », which no learner reads; a glossary with a comma variant, a qualified row used before its concept, a term used in a « Consigne au professeur » before its concept (which no learner reads), an empty English cell, and earlier uses silenced by a concept reference, one of them to an annex unit; in `sources.md`, a claim on two anchors, a « cours » claim with no verification, a `fait` claim on « Approfondissement », « Non vérifié » entries anchored to a unit and to the stances, stance items with `verified`); every check passes, and its `course.yaml` and the frontmatter of each `concept.md` are valid against `course/schemas/` under `Ajv2020`.
- `fixtures/broken/<name>/`: a copy of it with one defect, named after the check it breaks; its `EXPECT` file names the check that must fail and the message it must give, with the exit code its severity gives. No other check may fail (the test says so). `broken/course-yaml-unlisted-folder` also runs with `--concept 0`, where `course-yaml` passes.
- `cafe`, the spec's sample course, is no fixture: `course-specs/check-course course-specs/linear-course/1/course/samples/cafe` checks it, and a change to the spec reports its new failures there.
- `fixtures/lexicon.yaml`: the lexicon every run of the fixtures reads (`--lexicon`): the groups of `course/README.md` section 7, with the values of the spec's `course/lexicon.yaml`; change both together. A `--lexicon` that does not exist fails `course-yaml` as a tooling error (no rule), exit code 1.
- `fixtures/dispatcher/<name>/`: a `course.yaml` that `course-specs/check-course` refuses, `other-spec` (an unknown spec, `other@1`) and `unknown-major` (`linear-course@9`); the test also runs `course-specs/check-course` on `valid/`, with the default and with `--category writing`, which must pass.

The fixtures are plain files: change `valid/` and the broken copies together, then run the test. A new check of a course adds a script, the rules it verifies in `course/rules.yaml` (their `check`), from which `check-course` takes it, a row above with its category and severity, a row in the MAJOR's `README.md` section 5 and a broken fixture. A new test of the spec's own files is the directives' (`spec-directives/1/README.md` section 8).
