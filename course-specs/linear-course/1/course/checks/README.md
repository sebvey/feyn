# Checks of `linear-course`

Scripts that verify a course against the rules of `course/rules.yaml` (described by `course/README.md`; listed in the MAJOR's `README.md` section 5), run by `check-course`, beside the agent workflow `taught-check.js`, which it does not run (below); the tests of the spec's own files (`teacher/README.md`, `README.md`, `course/README.md`, `decisions/`, `course/rules.yaml`, `teacher/rules.yaml`, `teacher/composition.yaml`, `course/schemas/`, the two lexicons, `spec.yaml`, `CHANGELOG.md`), run by `spec-directives/check-spec`, belong to the spec directives this MAJOR follows (`spec-directives/1/tests/`) and are described in `spec-directives/1/README.md` section 8. Node 20 or later, CommonJS, run under `mise exec` like every tool here, with the `lib/` and the dependencies of the directives MAJOR that the MAJOR's `spec.yaml` declares (`directives: 1`, so `spec-directives/1/package.json`; decision `checks-use-ajv-and-yaml`): `directives.js` reads that line and loads them through a `createRequire` on that `package.json`. The course's YAML is read by the package `yaml` in YAML 1.2 mode, through `lib/yaml-lines.js`, which keeps the line of each key and item so a failure points at `file:line`; ajv compiles the schemas of `course/schemas/` through its class `Ajv2020` (JSON Schema 2020-12); Markdown and SVG are read by the small readers in `lib/` (`md.js`, `xml.js`), which cover the subset the spec uses. Each rule of `course/rules.yaml` names in `check` the script that verifies it, and `check-course` takes its checks from there (`lib/rules.js`). The form of the concept file is read from `course/form.yaml` (`check-course` passes it to `lib/course.js`, which finds the parts of each `concept.md`, its units and their fields, for every check that reads them): `concept-file`, `unit-contract` and `unit-length` hold a course to it, and `conventions` and `glossary-order` take from its `readers` the parts the learner reads. `concept-file` validates the frontmatter of `concept.md` through `Ajv2020` and `course/schemas/concept-frontmatter.schema.yaml`, a failure mapped from ajv's instance path to its `file:line`; `course-yaml` still verifies its schema rule with its own code, not through ajv.

## Install

```
mise exec -- npm ci --prefix spec-directives/1
```

From the repository root, once per clone or worktree, and again when `package-lock.json` changes: `npm ci` installs the locked versions in `spec-directives/1/node_modules/`, which git ignores. The command has no `cd`, so an agent in a worktree can run it. Without it, `check-course`, `test-fixtures`, `course-specs/check-course` and `spec-directives/check-spec` stop with one line giving that command (exit code 2); a missing `spec.yaml`, or a `directives` MAJOR with no folder, stops them the same way.

## Run

```
mise exec -- course-specs/check-course courses/<id>
mise exec -- course-specs/check-course courses/<id> --category pedagogy
mise exec -- course-specs/check-course courses/<id> --only svg-contract
mise exec -- course-specs/check-course courses/<id> --only concept-file,unit-contract --concept 9
mise exec -- course-specs/linear-course/1/course/checks/check-course --list
```

The checks come from the rule file of a course (`spec-directives/1/README.md` section 5; decision `severity-from-level-and-method`): `check-course` runs, in one run, every check named by the `check` of a rule of `course/rules.yaml` whose method is test. A check's category and level come from its rules, which `rule-files` (`check-spec`) holds to one category and one level per check, and its severity follows: it **blocks** when its rules are requirements verified by test, otherwise it **reports**. A failure of a blocking check sets exit code 1; a failure of a reporting check is printed the same way, its findings triaged into course issues, and leaves exit code 0. The blocking checks run first, then the reporting ones, each in the order of `course/rules.yaml`; no list of checks is written in `check-course`.

A check runs on a course when its method is test and its script is in this folder. The tests of `check-spec` (`spec-directives/1/README.md` section 8) verify no rule: `check-course` neither runs nor lists them. A check of another method is not run here: `taught-check` (analysis) is an agent workflow kept in this folder, `taught-check.js`, which `check-course` does not run, run as `course-specs/linear-course/1/README.md` section 5 says; and a rule verified by inspection has no check, the review reads it. `--list` names every check, the ones not run here with how they run.

`course-specs/check-course` reads `spec: linear-course@<MAJOR>` in the course's `course.yaml` and runs `course-specs/linear-course/<MAJOR>/course/checks/check-course` with the same arguments; it refuses an unknown spec or MAJOR, naming it, with exit code 2. The `spec:` line names the MAJOR, whose `spec.yaml` names, by its `directives:` line, the directives MAJOR whose `yaml` package (in `spec-directives/<MAJOR>/node_modules/`) then reads `course.yaml`: the dispatcher needs that `npm ci` too. This folder's `check-course` runs this MAJOR's checks directly, `--list` with no course included.

One line per passing check (`<id>: ok`), one line per failure (`<id>: fail: <file>:<line> <message>`, the file relative to the course folder), whatever the severity; then one summary line, `summary: <n> blocking checks, <n> failed (<ids>); <n> reporting checks, <n> failed (<ids>); exit <code>`. The exit code is 0 when no blocking check fails, 1 when one fails or a check crashes, 2 on a usage error, when the rule files cannot be read or when the dependencies are not installed.

| Option | Does |
|---|---|
| `--category <c>[,<c>]` | runs the checks of those categories only (repeatable): a closed list, the categories of a course in `course/rules.yaml` (`structure`, `pedagogy`, `writing`, `diagrams`, `sources`); an unknown one is a usage error |
| `--only <id>[,<id>]` | runs those checks only (repeatable); an unknown id (a test of `check-spec` among them), the id of a check not run here, or an id outside `--category` is a usage error |
| `--concept <number>` | the per-concept checks (`concept-file`, `unit-contract`, `unit-length`, `conventions`, `svg-contract`, `sources`, `glossary-order`) look at that concept only, and `course-yaml` demands only that concept's folder and does not look for unlisted folders in `concepts/`: for a migration in progress, when the other concept folders do not exist yet |
| `--lexicon <file>` | reads the lexicon of the course files from `<file>` instead of this MAJOR's `course/lexicon.yaml` (the fixtures' lexicons, `test-fixtures`) |
| `--list` | prints every check of `course/rules.yaml`, `--category` applied, in the order of the run: its id, its category, its severity (`blocks` or `reports`), and for a check not run here, how it runs; no course needed |

The flag `--quality`, removed, is a usage error whose one line names its replacement: the default run, which holds the reporting checks, or `--category`.

## The checks

One script per id, `course/checks/<id>.js`, exporting `run(ctx)`. The category and the severity are those `check-course --list` prints, from the rules, in the order of the run.

| Id | Category, severity | Script | Verifies (course/README.md) |
|---|---|---|---|
| `course-yaml` | `structure`, blocks | `course-yaml.js` | fields (no sections nor units: the map of the course), identifiers, order, domains, annexes, prerequisites, paths, no unlisted folder in `concepts/` (not looked for under `--concept`), spec declared; a missing or unreadable lexicon, a tooling error (no rule: the lexicon is the spec's, `lexicon-keys` of `check-spec` tests it) (2; `spec-directives/1/README.md` 6) |
| `concept-file` | `structure`, blocks | `concept-file.js` | from `course/form.yaml`: the files of the folder; the frontmatter against its schema through `Ajv2020`, then what the schema does not say (`verified` parallel to `refs`, absent without `refs`; an item's text in inline Markdown); the parts of `concept.md` in order (head, sections, foot) and no other `##`; the tree of the concept in its headings (section and unit ids: form, order, uniqueness, at most 9 units per section, a title after each id); the sections of `sources.md` and the column count of its tables (3, 3.1, 3.2) |
| `unit-contract` | `pedagogy`, blocks | `unit-contract.js` | from `course/form.yaml`: a section with units holds them only; each unit's fields (known labels, a qualifier on « Question » only, the mandatory ones once, in order, none empty), no line outside a field; « Idées fausses » a list of misconceptions in « », their follow-ups nested under them; each supplementary case, its heading (one qualifier of the lexicon's `qualifiers`), a title unique in the concept, the fields of a unit without « Matière » and « Consigne » (3.3, 7) |
| `conventions` | `writing`, blocks | `conventions.js` | the conventions of the text of `concept.md`, in the parts the learner reads (`readers` of `course/form.yaml`, the instruction left out): concept references, stance markers; no image in `concept.md`; a `####` only inside a unit; plain Markdown in every course file (1, 3.5) |
| `domain-first-sentence` | `writing`, blocks | `domain-first-sentence.js` | the first sentence of each paragraph of « Le fil des concepts » ends with `.`, `?` or `!` within 300 characters of the lead (4) |
| `svg-contract` | `diagrams`, blocks | `svg-contract.js` | every diagram against the drawing contract, a root `<defs>` accepted; declared and present diagrams, the `unit` of each a unit of the concept (3.1, 6.1) |
| `sources` | `sources`, blocks | `sources.js` | no introduction; in each « Affirmations » row of five cells (the column count is `concept-file`'s): section anchors that exist in `concept.md` among its published parts, a source cell of reference ids or the `markers.course` word, a verification (empty for a « cours » claim only), a nature (`markers` consensus, school, course, or `natures.fact`); reference ids, links (one URL or empty), types, dates; every id cited exists, every reference is cited by a claim or a frontmatter item; « Non vérifié » entries open with their section; `concept.md` cites no reference (3.1, 3.4) |
| `course-files` | `structure`, blocks | `course-files.js` | `plan.md` (« Public cible », « Accueil »: one posture paragraph, then its questions), `glossary.md` (four columns, one concept number in the fourth, no variant in two rows), `CHANGELOG.md`, domain files, no unlisted file in `domains/` (4, 5) |
| `domain-first-sentence-standalone` | `writing`, reports | `domain-first-sentence-standalone.js` | the first sentence of each paragraph of « Le fil des concepts » does not open with a word of the lexicon's `checks.anaphora` list; a lexicon without that list is a failure of this check (4, 7) |
| `typography` | `writing`, reports | `typography.js` | no banned character of the lexicon in course text (1) |
| `unit-length` | `pedagogy`, reports | `unit-length.js` | the text of « Matière », « Ancrage » and « Question » of each unit, counted in lines of 100 characters (its characters divided by 100): a unit above 12 is reported (`length` of `unit` in `course/form.yaml`) (3.3) |
| `glossary-order` | `pedagogy`, reports | `glossary-order.js` | no `concept.md`, in the parts the learner reads (`readers` of `course/form.yaml`: every field and follow-up, the head and the foot, but not the instruction) or its frontmatter (stance and neighbour texts, diagram titles and captions), uses a glossary term before its defining concept (the fourth column), unless the sentence carries a concept reference to that concept (`lib/refs.js`, the grammar `conventions` checks); every use is reported; each comma variant of the term cell is matched whole word, case ignored; a row whose term cell has a parenthesis is skipped (5) |

A claim's source cell holds reference ids (`[S1], [S2]`) or the `markers.course` word (« cours »), nothing else: free text (« aucune », « fil rouge ») and a path to another concept fail. A section anchor is a section or unit id, or a published part of the head or the foot by its lexicon value (the `head` and `foot` of `course/form.yaml` marked `published`: `headings.essentials`, `landmarks`, `deepening`) whose heading exists in `concept.md`; a « Non vérifié » entry is a list item `<anchors> : <text>`, and may also name `headings.stances`. The form of the verified cell (a quotation and its place) is reviewed.

## Tests of the spec itself

The tests of the spec's own files, run by `spec-directives/check-spec <spec-dir>`, belong to the spec directives this MAJOR follows: their list, what each verifies, their fixtures and how to run them are in `spec-directives/1/README.md` section 8.

## Tests

```
mise exec -- course-specs/linear-course/1/course/checks/test-fixtures
```

It tests the course fixtures and the dispatcher; the spec fixtures, under `spec-directives/1/tests/fixtures/`, are tested by `spec-directives/1/tests/test-fixtures` (`spec-directives/1/README.md` section 8). Every course fixture runs once, with the default; the test reads `course/rules.yaml` itself and holds each run's exit code to the severity of the check that fails: 1 for a blocking check, 0 for a reporting one. `--list` must name every check of `course/rules.yaml` with the category and the severity of its rules, and none of the tests of `check-spec`; a run must run every check `--list` does not mark "not run here". `--category` runs the checks of its categories only (`writing`, `pedagogy`, `structure,diagrams`; `broken/svg-contract` passes with `--category writing`); an unknown category (the name of the spec among them), the flag `--quality`, removed, an id of a test of `check-spec` and an id outside `--category` are usage errors (exit code 2).

- `fixtures/valid/`: a minimal valid course (three concepts, one annex, one diagram with a root `<defs>` declared at its unit; concept files with a section of two units and sections of one unit, every field of a unit, a field on several lines, a qualified « Question », a misconception with a follow-up, the three types of supplementary case, the three parts of the foot, an annex cut into units; a glossary with a comma variant, a qualified row used before its concept, a term used in a « Consigne » before its concept (which no learner reads), an empty English cell, and earlier uses silenced by a concept reference, one of them to an annex unit; in `sources.md`, a claim on two anchors, a « cours » claim with no verification, a `fait` claim on « Approfondissement », « Non vérifié » entries anchored to a unit and to the stances, stance items with `verified`); every check passes, and its `course.yaml` and the frontmatter of each `concept.md` are valid against `course/schemas/` under `Ajv2020`.
- `fixtures/broken/<name>/`: a copy of it with one defect, named after the check it breaks; its `EXPECT` file names the check that must fail and the message it must give, with the exit code its severity gives. No other check may fail (the test says so). `broken/course-yaml-unlisted-folder` also runs with `--concept 0`, where `course-yaml` passes.
- No real course is a fixture: `course-specs/check-course courses/po-essai` checks the bench course, and a change to the spec reports its new failures there.
- `fixtures/lexicon.yaml`: the lexicon every run of the fixtures reads (`--lexicon`): the groups of `course/README.md` section 7, with the values of the spec's `course/lexicon.yaml`; change both together. `fixtures/lexicon-no-anaphora.yaml`: the lexicon without the optional `checks.anaphora`; `valid/` with it fails `domain-first-sentence-standalone` only, a reporting check, so with exit code 0 (a reporting failure alone); `broken/course-files` with it fails a blocking and a reporting check, exit code 1. A `--lexicon` that does not exist fails `course-yaml` as a tooling error (no rule), exit code 1.
- `fixtures/dispatcher/<name>/`: a `course.yaml` that `course-specs/check-course` refuses, `other-spec` (an unknown spec, `other@1`) and `unknown-major` (`linear-course@9`); the test also runs `course-specs/check-course` on `valid/`, with the default and with `--category writing`, which must pass.

The fixtures are plain files: change `valid/` and the broken copies together, then run the test. A new check of a course adds a script, the rules it verifies in `course/rules.yaml` (their `check`), from which `check-course` takes it, a row above with its category and severity, a row in the MAJOR's `README.md` section 5 and a broken fixture. A new test of the spec's own files is the directives' (`spec-directives/1/README.md` section 8).
